# ポツ神ファインダー (potsugami) v0

田舎にポツンと佇む、観光地化していない小さな神社 — 「ポツ神」 — を、
**孤立度スコア**で発見するためのローカルバッチツール。

引き継ぎ書の叩き台 (「1県分で孤立度だけのスコア v0 を作り目視検証する。
石段フィルタは OSM `highway=steps` の網羅性をまず測る」) の実装。
1 コマンドで県単位の神社ランキング (CSV / GeoJSON / 単一ファイル HTML 地図) を出力する。

```
cd potsugami
pip install -e .          # requests + Pillow のみ。geopandas 等の重量級は不使用
potsugami run --pref 千葉県
open out/千葉県/map.html   # ブラウザで開く
```

ネットワーク不要のデモ (合成データ) も用意してある。出力の見た目はこれで確認できる:

```
potsugami demo --out out/demo    # examples/demo/ に生成済みサンプルあり
```

> **⚠️ 実データでの動作は未検証。** この開発セッションの実行環境は egress policy で
> Overpass API / 地理院タイルへの接続が遮断されていたため、ロジックはすべて
> 合成フィクスチャによる 116 のユニットテストで検証している。実データ特有の
> 想定外 (特に地理院ベクトルタイルの実レイヤ名・属性名) が残っている可能性がある。
> 初回は `--limit 30` で小さく実行し、結果が明らかにおかしければ
> `--gsi-source experimental` や `--buildings osm` に切り替えて切り分けてほしい。

## 1. 出力

`potsugami run --pref 千葉県` で `out/千葉県/` に:

| ファイル | 内容 |
|---|---|
| `map.html` | 単一ファイルの Leaflet 地図。スコア順ランキング、フィルタ (名前 / スコア / 拠点距離 / 石段 / 有名どころ除外)、ソート切替、**★候補・訪問済・除外の記録** (localStorage 保存。OSM ID キーなので再生成後も残る)。ベース地図は地理院淡色/標準/航空写真/OSM 切替 |
| `ranking.csv` | 全列入りランキング (BOM 付き UTF-8。Excel でそのまま開ける) |
| `shrines.geojson` | 同内容の GeoJSON (QGIS などで使う用) |
| `summary.txt` | 件数、石段データ網羅性の統計 |

各候補には**ディープリンク 5 本**が付く:
経路 (Google Maps ナビ・車) / 地理院地図 / Google マップ / ストリートビュー / OSM。
ホトカミ・Google の写真や口コミは規約上スクレイピングせず、
最終判断は人間がリンク先 (航空写真・ストリートビュー) で行う前提。

複数県をまとめて 1 枚の地図にもできる:

```
potsugami run --pref 千葉県 --pref 茨城県
```

## 2. ポツ神スコア v0.1 の定義

**距離減衰カーネル和** (人の気配の総量) を指数変換したもの。

```
P     = Σ_i a_i · exp(−d_i / τ)          τ = 180m (tau_m)
S_iso = 100 · exp(−P / 2.5)              (p_scale)

d_i : 神社から建物ポリゴン外周までの距離 (探索半径 1000m)
a_i : min(建物面積 / 80m², 5)。面積不明 (OSM 代表点) は 1.0
      無壁舎 (温室・車庫、ftCode 3103/3104) は ×0.3 で算入
最終スコア = S_iso × 騒がしさ係数 × 有名度係数
```

- **騒がしさ係数** (既定 ON、`--no-nuisance` で OFF):
  メガソーラー・工場地・採石場・残土処分場・ゴルフ場が 150m 以内なら ×0.5、
  400m 以内なら ×0.7。幹線道路 (国道・主要地方道クラス) 100m 以内で ×0.7。
  「建物がない」≠「静かで人がいない」の穴 (房総のメガソーラー隣接など) を塞ぐ。
- **有名度係数** (既定 ON、`--no-fame-penalty` で OFF):
  OSM の wikipedia / wikidata / tourism / heritage / website タグ 1 つにつき
  ×0.85〜0.95 (下限 0.5)。著名な奥宮・パワースポットが最上位を汚染するのを薄める。
  弱い係数なのは、タグの不在は「無名の証拠」ではなく単なる情報不足だから。

### なぜリング計数ではなくカーネル和か

初期案は「最寄り建物距離 + 同心リング内の建物数」の加重和だったが、
設計レビューで次の構造欠陥が判明したため置き換えた:

1. **田んぼの中の集落鎮守が山中のポツ神を逆転する** — 開けた農地では
   「近接建物ゼロ」が自動成立して大きな加点になり、水田越しに集落 30 戸が
   見えている鎮守 (S≈69) が、小屋 1 棟だけの深山の社 (S≈61) を上回っていた。
   カーネル和では集落 30 戸 ≈ 7 点、小屋 1 棟 ≈ 77 点、無建物 = 100 点と正しく並ぶ。
2. **300m で飽和し、最上位が巨大な同点タイになる** — カーネル和は 1000m 付近まで
   順序が残る (同点タイブレークは最寄り建物距離の降順)。
3. **リング境界 ±2m でスコアが約 9 点跳ぶ** — 連続関数なので境界がない。
4. **建物の規模を無視** — 面積重みで工場 1 棟と物置 1 棟を区別する。

パラメータはすべて `--param key=value` で上書きできる (例: `--param tau_m=250`)。
定義は `src/potsugami/config.py` の `ScoreParams` / `NuisanceParams`。

### 境内建物の自己除外 (重要な誤差源)

社殿・社務所自身が建物データに載っているため、2 段構えで除外する:

1. 重複排除時に神社へ統合された OSM 要素 (`building=shrine` の社殿ポリゴン等) の
   座標から 30m 以内の建物は除外 (幾何学的除外)
2. 神社中心から 40m (`self_exclusion_m`) 以内は無条件で除外 (フォールバック)

それでも **(a) 参道が長く神社ノードが鳥居側にある神社は自分の拝殿で減点される**、
**(b) 農家の敷地隅の屋敷神は母屋が除外されて偽ポツ神になる**、の両方向の誤りが残る。
(b) の検出用に、除外した建物の数を `n_adjacent` 列に出している —
**`n_adjacent ≥ 1` の高スコア候補は目視時に屋敷神を疑うこと**。
根本対策 (建物ポリゴンの連結クラスタによる境内推定) はロードマップ参照。

## 3. データソースと設計判断

| データ | ソース | 選定理由 |
|---|---|---|
| 神社 | OSM (Overpass API)。`amenity=place_of_worship + religion=shinto` ∪ `building=shrine` ∪ 名前が神社系で religion 未記入の place_of_worship | 即座に使える唯一の全国リスト。**ただし無名の小神社ほど OSM に載っていない母集団バイアスがある** (下記「限界」) |
| 建物 (孤立度の分母) | **地理院ベクトルタイル** (最適化ベクトルタイル `optimal_bvmap-v1`、建物レイヤ BldA、z16) | 基盤地図情報由来で**全国均一の被覆**。OSM の建物は田舎で歯抜けが多く、未記入の集落が偽ポツ神になるため不採用 (`--buildings osm` で切替は可能)。旧提供実験タイルは終了予告があるため既定にしない (`--gsi-source experimental` で切替可) |
| 石段 | OSM `highway=steps` (`out geom`) | 引き継ぎ書 5 章の仮説どおり。県単位で全件取得し 120m 以内の神社にマッチ |
| 標高 | 地理院標高タイル `dem5a → dem5b → dem5c → dem10B` の順でフォールバック | 石段の標高差→段数レンジ推定 (段数 ≈ Δh / 0.18〜0.30m)。`step_count` タグがあればそちらを優先。10m メッシュ (±5m 級) しか引けなかった場合は `elev_low_precision` 列に低精度フラグ |
| 騒がしさ | OSM (ソーラー発電所・landuse・幹線道路) | 上記の騒がしさ係数 |
| 車道アクセス | OSM 道路 (上位 400 候補のみ、`--roads-top` で変更) | 孤立度上位は「徒歩数時間の奥宮」に退化しがち。車で行けるかの検証列 (`road_dist_m`)。スコアには入れない |

その他の設計判断:

- **形態: ローカルバッチ CLI + 静的 HTML。** 個人ツールにサーバは不要で、
  データのライセンス整理も一番単純。山間部でもファイルさえあれば地図の骨格は開ける。
- **全 HTTP 応答をディスクキャッシュ** (`.potsugami_cache/`)。再実行・パラメータ調整は
  ネットワークゼロで回る。スコアのつまみ回しはキャッシュ済みデータに対して行える。
- **MVT (ベクトルタイル) デコーダは純 Python 自作** (`src/potsugami/mvt.py`, 約 200 行)。
  protobuf 依存を避けるため。テストは自作エンコーダとのラウンドトリップで担保。
- **タイル境界の建物二重カウント対策**: 各建物はその重心が属するタイルにのみ帰属させる
  (クリップバッファ由来の重複を除去)。タイルをまたぐ建物は 2 分割のまま両側で
  数えられるが、面積重み方式では合計面積がほぼ保存されるため実害は小さい。
- **重複排除は名前考慮**: 60m 以内の要素を統合するが、双方に異なる名前が
  付いている場合 (隣接する別法人の神社) は統合しない。
- 実行規模の目安 (千葉県): 神社 数千社、建物タイルは神社周辺のみで
  1〜3 万枚程度 (キャッシュ後は再取得なし)。Overpass はクエリ数本 + バッチ数十本。
  タイル取得は 50ms 間隔、Overpass は 2s 間隔で叩く行儀設定にしてある。

## 4. 既知の限界 (v0 で承知の上のもの)

1. **母集団バイアス (最重要)**: 「OSM に登録される程度には知られた神社」の中から
   探している。無名の小神社ほど OSM 未収録で、そもそも候補に出てこない。
   千葉県神社庁の包括社だけで千社超あり、OSM の件数がそれをどれだけ下回るかで
   欠落規模が測れる (検証手順参照)。対策の本命は地理院の神社記号 (鳥居記号) の
   取り込み (ロードマップ)。
2. **廃集落**: 建物ポリゴンは住人の有無を知らない。全戸離村した集落の神社
   (実際は完全に静か) は低スコアに沈む。国勢調査人口メッシュの突合で治せる (ロードマップ)。
3. **海岸・湖岸**: 探索圏の半分が水面だと構造的にスコアが上がる。
   「海辺のポツ神」は発見対象として望ましい面もあるため v0 では補正しない。
4. **石段の誤マッチ**: 120m 近接という緩い条件なので、隣接する公園・学校・墓地の
   階段を拾うことがある。`steps_match_dist_m` 列 (マッチ距離) を信頼度の目安に。
5. **段数推定はレンジ**: 蹴上げ 0.18〜0.30m の仮定による推定であり「約 120〜200 段」の
   精度。`elev_low_precision=True` の行の Δh は信用しない。
6. **地理院ベクトルタイルのレイヤ名・属性名は実タイルで未確認** (開発環境の
   ネットワーク制約による)。建物レイヤ名は BldA / building / 建築物 の部分一致で
   探すが、実際に 0 件が続く場合はレイヤ名の食い違いをまず疑うこと
   (`config.py` の `GSI_BVMAP_SOURCES` で調整できる)。

## 5. 検証の進め方 (v0 の本題)

引き継ぎ書 10 章の「スコアが体感と合うか」の確認は、上位だけ眺めると
偽陰性 (沈んだ良い神社) を永遠に見逃すので、次の手順を推奨する:

1. **上位 30 社の目視** — map.html から航空写真・ストリートビューで確認し、
   ✕だったものに原因タグを付ける (境内リーク / ソーラー / 屋敷神 / 廃集落 / その他)。
   ✕の原因分布がそのまま次に直すべき項目になる。
2. **層化サンプル** — スコア十分位から各 5〜10 社を無作為に見て、
   「体感のポツ度 (1〜5)」を付ける。スコアとの順位相関 (Spearman ρ ≥ 0.7 目安) を見る。
3. **網羅率の実測** — 市町村を 1 つ選び、県神社庁の一覧と OSM 由来の候補リストを
   突き合わせて欠落率を測る。ここが大きいなら v1 の最優先は神社記号の取り込み。
4. **石段網羅性** — summary.txt のマッチ率が判断材料。
   目安: 30% 以上なら石段フィルタとして実用、10% 未満なら OSM 単独では不足で、
   引き継ぎ書 5 章の DEM ベース (鳥居記号と社殿の標高差) に切り替える。

## 6. ライセンス・利用規約の整理

- **地理院タイル** (標高・ベクトル・地図表示): 国土地理院コンテンツ利用規約に基づき
  出典明記で利用可。map.html の帰属表示に「地理院タイル」リンクを入れてある。
- **OSM データ**: © OpenStreetMap contributors, **ODbL**。個人の手元利用は問題ないが、
  生成した CSV / GeoJSON / 地図を**公開・配布すると派生データベースとなり
  ODbL の share-alike 義務が発生する**。v1 で Web 公開する前にここを整理すること。
- **Overpass API**: 公共インスタンスのため節度ある利用 (このツールは UA 明記・
  リクエスト間隔・ミラーフォールバック・全応答キャッシュを実装済み)。
- **OSM ラスタタイル** (map.html のベース地図の 1 つ): tile.openstreetmap.org の
  利用ポリシー対象。個人利用の範囲なら問題ないが、公開アプリの既定タイルにはしない。
- **ホトカミ / Google マップ**: スクレイピング不可の前提。本ツールはディープリンクで
  人間を送り込むだけで、データは一切取得しない。

## 7. ロードマップ (v1 以降の候補)

効果が大きい順:

1. **地理院ベクトルタイルの神社記号・注記の取り込み** — 母集団バイアス (限界 1) の
   本命対策。MVT デコーダは実装済みなので、記号レイヤの抽出を足すだけで
   「OSM に載っていない神社」も候補化できる。注記 (社名) の有無は
   引き継ぎ書 3 章の「地理院地図で社名が注記されていない = 小さい神社」の
   代理指標にもなる。
2. **国勢調査 250m/500m 人口メッシュ** — 廃集落の救済 (限界 2) と、
   建物ゼロ地帯の同点タイブレーク。
3. **所要時間フィルタ (OSRM)** — 「東京から車で 2 時間」を直線距離でなく
   実走行時間で。数百候補の table API は一括数秒で引ける。
4. **写真エンリッチ** — Wikimedia Commons geosearch でサムネイル表示。
   「新海誠的かどうか」の確認導線。
5. **境内の連結クラスタ推定** — 自己除外の両方向誤り (2 章) の根本対策。
6. **クライアント側の重みスライダ** — geojson にはスコア成分の生値が
   すべて入っているので、map.html 内で再計算・再ランキングできる。
7. 式内社リスト・神社庁リストの突合、駐車場 (`amenity=parking`) 距離、
   参道の向き (朝日/夕日)、ハシゴ計画 (複数経由地の経路リンク)。

## 8. 開発

```
cd potsugami
pip install -e ".[dev]"
python -m pytest            # 116 tests, ネットワーク不要
```

構成 (`src/potsugami/`): `shrines.py` (取得・重複排除) → `buildings.py`
(建物プロバイダ: gsi/osm) → `isolation.py` (カーネル和スコア) →
`nuisance.py` / `fame.py` (減点係数) → `steps.py` + `dem.py` (石段・標高) →
`roads.py` (車道距離) → `pipeline.py` (統括) → `report.py` + `map_template.html` (出力)。
`overpass.py` / `tiles.py` / `cache.py` が HTTP 層 (すべてディスクキャッシュ)。
`mvt.py` は純 Python の Mapbox Vector Tile デコーダ。

外部 API を叩く前にクエリを確認したいときは `potsugami query --pref 千葉県`。
